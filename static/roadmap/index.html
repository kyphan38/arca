5 nguyên tắc cốt lõi

1
Feynman Technique — hiểu trước khi build
Đọc concept → đóng sách → giấy trắng, giải thích như đang dạy người mới. Chỗ bị kẹt = chỗ chưa hiểu → đọc lại. Lặp lại cho đến khi trôi chảy. Viết blog = Feynman ở scale lớn.
2
Spaced Repetition — không cramming
Dùng Anki — mỗi concept = 1 flashcard. Review: ngày 1 → 3 → 7 → 14 → 30. Sau 5 lần, concept gần permanent. Mỗi buổi học BẮT ĐẦU bằng 15-20 phút Anki review.
3
Deliberate Practice — tập trung chỗ yếu
1 project vật lộn với distributed consensus > 5 projects hello-world. Chỗ khó = chỗ đang học. Yếu distributed systems → 80% thời gian cho nó.
4
Interleaving — xen kẽ theory ↔ practice
Đọc DDIA partitioning → code consistent hashing → đọc Dynamo paper → modify code → viết blog. Xen kẽ liên tục, không tách rời.
5
Teach to Learn — dạy để hiểu
Viết blog buộc bạn hiểu thật sự. Nếu không giải thích được cho junior hiểu → chưa đủ sâu. 1 bài/tháng, mỗi bài deep-dive 1 concept.

Cấu trúc phỏng vấn tại FAANG cho Platform/Infra ML role

Vòng 1: ML System Design (45-60 min) — quan trọng nhất
Ví dụ đề thực tế:
• "Design a feature store for a ride-sharing company serving 10M requests/day"
• "Design a distributed training system for 1000-GPU cluster"
• "Design an ML platform that lets data scientists self-serve model deployment"

Họ muốn thấy: scalability thinking · data consistency tradeoffs · failure modes · developer experience · cost awareness. Không chỉ "dùng tool X" — mà "tại sao, trade-off là gì?"
Vòng 2: Distributed Systems Deep Dive
Câu hỏi loại: "How does Raft consensus work?" · "What happens when a Kafka partition leader fails?" · "Explain consistent hashing and when you'd use it in ML context" · "How do you ensure exactly-once semantics in a feature pipeline?"

Đây là vòng tách biệt Platform Eng. candidate. Nếu không trả lời được → bị filter ngay. DDIA + MIT 6.824 cover gần hết.
Vòng 3: Coding (Python + infra)
Ít algorithm thuần hơn SWE. Thiên về: implement một LRU cache · design một job scheduler · write Python SDK với clean API · debug một distributed tracing scenario. LeetCode Medium 50 bài là đủ.
Vòng 4: Behavioral — với Platform Engineer twist
"Tell me about a time you built something other engineers used" — đây là câu hay nhất để phân biệt Platform Eng. candidate thực sự.

"How did you handle competing requirements from different teams using your platform?"
"Describe a time your platform had an outage. How did you handle it and prevent recurrence?"

15 STAR stories chuẩn bị sẵn. Mỗi story cần số liệu cụ thể.
